## 1. 总览

- 模块:共 5 个;对象:自建 17 个 + 复用平台对象 2 个(`sys_business_unit`、`sys_user`),其中共享对象 4 个(见 §3)
- 能力类别用量:对象 17 / 视图 对象视图 17(每对象列表 + 表单)+ 命名列表视图 33(grid 30 / kanban 2 / timeline 1)+ 内联编辑列表 7 / 按钮 16 / 流程与审批 0 条平台流程 + 1 套自建审核状态机 / 权限集 6 + 岗位 6 + 共享规则 静态 0(按方案发布动态生成:每个方案的参与主体 / 分管领导 / 到人分工三类)/ 报表 3 + 看板 2 + 数据集 3 / 导入导出涉及 3 对象 / 通知 0 / 定时任务 0 / 定制点 6 / 端覆盖 纯 Console
- 定制点:共 6 个(自定义页面 0 / 服务端代码点 6 / 其他 0)——计分引擎、审核状态机、方案发布生成、调整落地重算、归档快照与只读锁、结果汇总生成
- 外部集成接口:**零外部集成**(已扫需求 V1.3 全文;§1.3「数据接入」仅指填报与批量导入,无外部系统对接)
- 对账:无报价清单可对账(已在本文 §6 记录,2026-09-02 已报 PM)
- 待验证:遗留 0 条(pre-intake 无待验证项)

## 5. 模块依赖与建议开发顺序

| 后继模块 | 依赖 | 理由 |
|---|---|---|
| M2 指标库 | M1 | 指标的责任板块引用组织单元 |
| M3 考核方案 | M1、M2 | 指标下达引用指标与主体 |
| M4 填报与审核 | M3 | 填报单由方案发布生成;状态机读方案流程节点 |
| M5 汇总与归档 | M4 | 结果与快照来自审批通过的填报单 |

**建议开发顺序(拓扑序)**:第 1 批:M1 + M2;第 2 批:M3;第 3 批:M4(先计分引擎后状态机);第 4 批:M5。无环。
