复杂场景说明:

- **S-08 类 Excel 填报**:需求明确「业务部门对 excel 情有独钟」,要把在线表格与指标定义、流程整合。平台没有电子表格组件,但有列表内联编辑、主从明细网格、xlsx 导出与 CSV/xlsx 导入,能覆盖「按行录入、即时算分、批量导入」;跨 sheet 自由公式不复制到系统,由指标计分规则承接(见 S-09)。
- **S-09 计分引擎**:现行 Excel 公式「跨表跨 sheet 很常见」,平台公式字段只能引用本记录字段、不能跨对象,因此计分不能靠公式字段,要写服务端计分引擎(定制点)。引擎口径要唯一、可重放。
- **S-14 到人折算**:需求只给了「到人分工(权重、个人系数)」「个人承接项(权重、目标)」两个概念,没有给合成公式,列为疑点 Q-03。

## 2. 平台能力覆盖度初判

**汇总:原生 12 / 需定制 4 / 做不了 0 / 待验证 0(共 16 场景)**

|---|---|---|

| S-02 | 原生支持 | 权限集(对象级 + 字段级)+ 读写范围 `own / unit / unit_and_below / org` + 岗位分发 + 条件共享规则;四级数据范围逐一有对应 |
| S-03 | 原生支持 | 平台账号体系(密码策略、锁定、失败计数、MFA、封禁)与审计日志对象;白名单归部署层配置 |
| S-04 | 原生支持 | 对象建模 + 字段历史跟踪(trackHistory)+ 状态机校验;版本以「新版本记录 + 上一版引用」表达 |
| S-05 | 原生支持 | 对象与主从关系、内联明细网格、状态机校验、发布前完整性检查用 hook 校验 |

| S-08 | 原生支持(有边界) | 列表 `inlineEdit`、主从 `inlineEdit: 'grid'`、xlsx 导出、导入向导(CSV;xlsx 走导入 API);**不支持**自由公式与跨 sheet 引用——这是有意收敛,不是缺口 |
| S-09 | 需定制(服务端逻辑) | 公式字段不能跨对象;计分引擎作为独立代码模块由 hook 在保存时调用,规则数据化(线性 / 阶梯 / 区间 / CEL 公式);平台 CEL 引擎可复用 |
| S-10 | 需定制(服务端逻辑)| 平台审批节点支持多级、并行(unanimous / quorum / per_group)、退回修订,但**驳回原因必填不能声明式强制**,且节点顺序写死在流程元数据里、不能随方案版本冻结;推荐自建审核状态机(见蓝图 §2.4 与方案分级 D-03) |

| S-12 | 原生支持 | 单对象 + 状态字段 + 审批留痕 |
| S-13 | 原生支持(重算联动在 S-09 引擎内) | 调整申请对象 + 审批 + hook 在通过时回写并触发重算 |
| S-14 | 原生支持(折算在 S-09 引擎内) | 汇总字段(sum/avg/count,带过滤)+ 数据集(维度、度量、派生比率)+ 仪表盘 + 矩阵报表钻取 |
| S-15 | 原生支持 | 只增对象 + hook 拒绝改删 + 权限集不授予编辑 |
| S-16 | 原生支持 | 平台审计捕获常开,`sys_audit_log` / 记录历史页签;审批与驳回动作另有审核记录对象 |

**「做不了」与「待验证」**:无。四个定制点全部落在平台 hook / 函数扩展机制内,不改平台包。

## 3. 风险点清单(高→低)

**R-高-01(业务)**:计分与到人折算口径未定——需求只描述了概念(完成率、权重、个人系数、承接项、加减分),没有给合成公式、封顶保底、逆向指标(越低越好)处理(§1.1、§1.4)
- 若成真的后果:引擎按推断口径开发,验收时与人力部 Excel 对不上,计分模块整体返工;考核结果与薪酬挂钩,口径争议直接引发员工申诉
- 建议动作:开工前拿到现行考核 Excel 模板与公式,按疑点 Q-01~Q-05 逐条拍板;引擎设计成规则数据化,口径改动不改代码

**R-高-02(技术/业务)**:「遵循 Excel 使用习惯」期望值可能超出平台内联网格能力(自由公式、跨 sheet、合并单元格、宏)(§1.2、§4 易用性)
- 若成真的后果:业务部门拒用,回到线下 Excel,系统沦为汇总录入工具
- 建议动作:第一轮演示就用真实指标表做内联填报 + xlsx 导入导出,让业务方确认「表格式录入 + 系统算分」可接受;把「自由公式不进系统」写进范围边界

**R-中-01(业务)**:方案「每月、每季度都可能不同」且流程也会调整(§1.1)——若每次调整都要改配置,人力维护负担大
- 若成真的后果:方案配置成为瓶颈,实施后仍靠人工
- 建议动作:方案版本支持复制上一版为起点;流程节点数据化随方案版本冻结

**R-中-02(技术)**:分公司「并行核对」与「驳回退回上一节点」在自建状态机里要处理多方并发(14 家分公司同时核对同一方案)
- 若成真的后果:并发下状态错乱,出现「已核对」被覆盖
- 建议动作:核对任务按分公司拆成独立记录,状态机只在「全部核对完成」时聚合推进;自测覆盖并发用例

**R-中-03(业务)**:组织架构、人员与分管关系数据未提供(§2.1 分管领导、§1.4 到人分工)
- 若成真的后果:试运行卡在主数据准备
- 建议动作:实施阶段用 impl-data 模板尽早收集;开发期用演示种子数据

**R-中-04(商务)**:验收标准、工期、付款等条款材料未提供(附录 D 六项全部「未提及」)
- 若成真的后果:验收扯皮、尾款无期
- 建议动作:签约前补齐;验收以 SRS 签字版逐功能可实测标准为准

**R-低-01(技术)**:大数据量表格(14 家分公司 × 数十指标 × 到人)的内联编辑性能(§4 性能)
- 若成真的后果:页面卡顿
- 建议动作:填报单按主体拆分,每张表控制在百行内;分页与筛选默认开启

**R-低-02(技术)**:xlsx 导入在平台上走 API 层而非声明式向导
- 若成真的后果:导入入口需要自定义按钮承载,多一个定制点
- 建议动作:第一版用平台 CSV 导入向导 + xlsx 导出模板;xlsx 直导列入二期

## 4. 疑点清单(业务语言,可直接转发客户)

**Q-02(计分 · 模糊 · 出处:§1.1「完成率」)**
对于「越低越好」的指标(如投诉率、成本超支率),完成率如何计算?A. 目标值 ÷ 实际值;B. 1 −(实际 − 目标)÷ 目标;C. 由各指标单独定义。

**Q-03(汇总 · 缺失 · 出处:§1.4 到人分工、个人承接项)**

**Q-04(调整 · 缺失 · 出处:§1.3 加减分)**

**Q-05(计分 · 模糊 · 出处:§1.1「分管领导的 kpi」)**
分管领导得分如何计算?A. 分管范围内各主体得分按主体权重加权平均;B. 领导本人另有指标;C. 两者相加。

**Q-11(归档 · 缺失 · 出处:§3 第 7 步)**

### C. 覆盖度逐条依据

平台能力依据来自 ObjectStack 源码(`packages/spec/src/**`)与参考应用(`examples/app-showcase`、`examples/app-crm`),关键结论:

- 组织单元:`sys_business_unit`(name / code / kind / parent_business_unit_id / manager_user_id)——S-01;
- 权限:`definePermissionSet` 的 `objects`(含 `readScope` / `writeScope`:own / own_and_reports / unit / unit_and_below / org)与 `fields`(`对象.字段` 级 readable / editable)、`definePosition`、`defineSharingRule`(criteria 条件共享)——S-02;
- 审计:对象 `enable.trackHistory` + 字段 `trackHistory`;平台审计捕获常开(`sys_audit_log`、`sys_activity`)——S-16;
- 校验:`state_machine` / `script` / `cross_field` 校验类型;hook 抛错拒绝写入——S-05、S-10;
- 表格:列表视图 `inlineEdit: true`、主从字段 `inlineEdit: 'grid'`、`exportOptions.formats: ['csv','xlsx']`、对象 `userActions.import`(CSV 向导)、导入 API 支持 xlsx——S-08;
- 公式字段只投影本记录字段,不支持跨对象引用(`packages/objectql/src/engine.ts` 注释、`cel-to-filter.ts` 拒绝跨对象遍历)——S-09 判需定制;
- 汇总字段 `Field.summary`(count / sum / min / max / avg,支持 filter);数据集 `defineDataset`(维度、度量、派生 ratio)、仪表盘、`defineReport`(matrix,drilldown)——S-14;
- 审批节点 `approval`(approvers 按 position / field / manager;behavior first_response / unanimous / quorum / per_group;`approvalStatusField`;revise / resubmit 回退边)——S-10 原生部分;驳回评论必填无声明式开关(`ApprovalNodeConfigSchema` 为 strictObject,无 requireComment;`decisionOutputs.required` 只在 approve 生效)——S-10 判需定制;
- 页面组件注册表无电子表格组件——S-08 边界。
