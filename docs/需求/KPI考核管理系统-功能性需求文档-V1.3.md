# KPI 考核管理系统 功能性需求文档

- 文档版本：1.3
- 更新日期：2026-09-02
- 适用对象：业务方、产品、实施与验收人员
- 说明：本文档仅描述业务需求（角色、流程、功能与规则），不涉及任何技术实现。

---

## 1. 项目概述

### 1.1 现状

在每个考核周期开始时（月度、季度、半年、年度等等），人力部会通知每个业务部门要给出每个部门的考核方案，每个部门都要基于excel表来设立各自的kpi指标（包含月度目标、季度目标、年度计划，完成率等等，对自己部门、对下级不同分公司都要设立对应的指标，同时业务部门还要和分公司人员商议每个指标是否有争议），不同kpi指标数据来源不同，计算方式不同，权重也不同，业务部门设定好计算公式（公式较为复杂，跨表跨sheet很常见），通过excel表计算好后再发给人力部门审核，人力部门再依据公司的考核规则，汇总业务部门的结果，再依据不同业务的考核权重、计算规则，做一张汇总表计算每个部门的kpi指标、每个分公司的指标、每个部门到人的不同kpi指标、每个分公司不同分管领导的kpi指标，然后再给上级领导审核，审核通过后再依据这个kpi指标的结果来计算每个人的绩效，整个过程有几个难点：
- kpi指标在每个部门和人力部门之间会来回很多次，都是通过聊天工具、excel传递；
- 每个部门需要和不同的分公司核对数据、调整，也是需要来回很多次，这就导致整个流程很冗长，效率很低，来回很多次，而且会经常出现指标与预期差异产生的争议；
- 都是通过excel来计算，纯人工核对，数据的调整、公式的设立、指标的调整，都是无法回溯的，人工核对的过程也是很漫长，且很容易出错；
- 原excel考核表中公式较为复杂，公式很多涉及到跨表跨sheet；
- 业务考核方案调整频繁，每月、每季度都有可能不同；
- 流程审核也会出现调整。

### 1.2 目标

面向多部门、多分公司的 KPI 考核管理，覆盖「指标库 → 方案配置 → 指标下达 → 数据填报 → 并行核对 → 审核流程  → 实时计分 → 数据调整流程 → 汇总 → 归档快照」的完整业务闭环。

建设目标：

- 统一考核口径：指标定义、计分规则、权重与目标值集中管理、版本可追溯；
- 流程可配置：流程定义、上下级关系、审核
- 全流程线上化：填报、核对、审核、审批线上流转，杜绝线下台账；
- 自动计分：填报后即时出分，计分过程透明、可逐条复核；
- 多维汇总：支持部门、分公司、到人、分管领导不同视角看考核结果；
- 全程留痕：所有数据变更与审批动作可审计；
- 操作简便：业务部门对excel情有独钟，需要兼顾他们的操作习惯，能将在线电子表格与指标定义、流程审批等整合起来

### 1.3 范围

指标管理、考核方案、数据填报、审批流程、计分与结果、加减分、数据调整（源数据调整、计算结果调整）、审计查询、组织与权限、数据接入与归档。

### 1.4 业务术语

| 术语 | 说明 |
|---|---|
| 考核方案 / 方案版本 | 一次考核的配置集合，支持多版本并存，发布后即冻结 |
| 考核主体 | 被考核对象（总公司各业务部门 + 14家分公司） |
| 部门板块 | 指标的责任部门（考核部门） |
| 考核关系 | 「谁考核谁」的配置关系 |
| 指标下达 | 分配到各考核主体的指标权重与目标值 |
| 到人分工 | 员工与部门板块的对应关系及其权重、个人系数 |
| 个人承接项 | 员工个人承担的具体指标及权重、目标 |
| 考核周期 | 月 / 季 / 半年 / 年 |
| 归档快照 | 某周期结果归档后的不可变留存 |

## 2. 用户角色与权限

### 2.1 角色职责

| 角色 | 主要职责 |
|---|---|
| 系统管理员 | 系统配置、用户/角色/组织维护，可访问全部功能与数据，流程定义 |
| 人力审核 | 指标与方案维护、考核审核、数据调整审批、审计查询 |
| 人力负责人 | 考核审核审批、数据调整审批、审计查询 |
| 部门填报人员 | 本部门数据的填报与提交，发起数据调整申请， |
| 分公司核对人员 | 本分公司的数据核对与审批 |
| 分管领导 | 分管范围内结果查看与最终审批 |

### 2.2 数据可见范围

系统按角色的数据范围控制可见与可操作的组织：

- 全部范围：可见全部主体；
- 分管范围：可见所辖组织及其下级；
- 本部门范围：仅可见本部门（或本分公司）；
- 仅本人范围：个人维度再收窄到本人。

业务要求：任何用户只能查看和操作其数据范围内的数据；越权访问应被明确拒绝；所有
业务操作的经办人以登录账号为准，不可冒名。

### 2.3 账号与安全（业务要求）

- 账号密码登录，密码强度与过期策略由系统强制；被停用账号立即失效；
- 连续登录失败应被限制，防止暴力破解；
- 生产运行必须使用高强度密钥与访问来源白名单；
- 敏感操作（审批、驳回、归档）必须留痕。

## 3. 核心业务流程

1. **配置方案**：新建方案版本 → 选择指标 → 分配权重与目标 → 配置考核关系与参与范围 →
   发布前完整性检查。
2. **发布**：冻结参与范围、流程与考核口径，生成指标下达与到人分工，发起流程。
3. **填报**：按填报视图录入数据（或批量导入）→ 自动保存 → 即时算分 → 提交（数据冻结）。
4. **核对与审核**：各分公司并行核对 → 人力审核 → 领导审批；驳回时退回上一环节并注明原因。
5. **计分**：系统按既定口径自动计算每个指标得分。
6. **汇总**：按部门、分公司、到人、分管领导四个维度汇总展示，可钻取到每个指标的得分明细。
7. **归档**：审批通过后生成不可变的周期快照，此后数据锁定不可再改。

流程节点顺序：部门填报 → 分公司核对（并行）→ 人力审核 → 领导审批 → 可归档。
驳回规则：驳回必须填写原因，流程退回上一节点重新处理，全程留痕。

---

## 4. 非功能需求（业务视角）

- 安全性：账号体系与访问控制完备，越权不可见、不可操作；敏感配置在生产环境必须强约束；
- 可靠性：得分口径唯一且可重复计算，历史周期结果稳定不漂移；所有变更可追溯；
- 易用性：遵循excel使用习惯，填报即时出分并给出校验提示；结果可逐层钻取；驳回原因必填等引导完整；
- 性能：常规页面与报表操作响应流畅，大数据量表格可正常浏览与编辑；
- 可扩展性：新增计分口径、考核关系、视图可通过配置实现，不影响已有考核数据。
