## 一页纸摘要

- **做什么**:一套面向总公司各业务部门与 14 家分公司的 KPI 考核系统,把「指标库 → 方案配置 → 指标下达 → 数据填报 → 并行核对 → 审核流程 → 实时计分 → 数据调整 → 汇总 → 归档快照」全流程搬到线上,替代现在靠 Excel 与聊天工具来回传递的做法。
- **怎么做**:基于 ObjectStack 低代码平台构建,组织、账号、权限、审计、导入导出等基础能力直接复用平台;考核专属的计分规则、审核流程、汇总口径由系统内置的规则引擎承担,口径改动只改配置不改代码。
- **保留 Excel 习惯**:填报采用「一张表一个考核主体」的网格录入,按行填实际值即时出分;支持 Excel 导出与批量导入;但**自由公式与跨表引用不进系统**——公式的作用由「指标计分规则」统一承担,这是本方案与现状最大的口径变化(见 §9 决策 13)。
- **需要您确认的**:12 项已按推荐口径给出产品默认(可改)、3 项需求未写明的疑点、2 项范围边界,共 17 项,见 §9。
- **现状**:按本方案已搭出可运行原型并跑通全流程(发布 → 填报 → 提交 → 分公司核对 → 驳回 → 审核 → 通过 → 加减分 → 调整 → 归档);确认后按确认结果调整,再进入正式开发与验收。

## 1. 建设目标与范围

**目标**(需求 §1.2):统一考核口径、流程可配置、全流程线上化、自动计分、多维汇总、全程留痕、操作简便。

**范围**(需求 §1.3):指标管理、考核方案、数据填报、审批流程、计分与结果、加减分、数据调整(源数据 / 计算结果)、审计查询、组织与权限、数据接入与归档。

**不在本期范围**:手机端(需求未提及,见 §9 疑点 Q-12)、与外部系统的数据接口(需求「数据接入」指填报与批量导入)、不同部门走不同审核流程。

## 2. 角色与数据范围

| 角色 | 在系统里做什么 | 能看到的范围 |
|---|---|---|
| 系统管理员 | 维护组织、用户、岗位;配置审核流程节点 | 全部 |
| 人力审核 | 维护指标库与考核方案、发布方案、人力节点审核、审批数据调整与加减分、审计查询 | 全部 |
| 人力负责人 | 人力节点审批、审批数据调整与加减分、审计查询 | 全部 |
| 部门填报人员 | 填报本部门数据并提交;发起数据调整申请、加减分申请 | 本部门 |
| 分公司核对人员 | 核对与本分公司相关的指标数据:确认或提出争议 | 本分公司 |
| 分管领导 | 查看分管主体的填报与结果,做最终审批 | 分管范围 |

数据范围的实现方式:系统按「谁是哪个组织的成员」和「方案里谁分管哪个主体」自动放开可见范围,组织调整或分管关系变化不需要改系统配置;越权访问被明确拒绝;所有操作的经办人以登录账号为准,审批人、提交人等字段由系统盖章,不能手工填写。

## 3. 核心业务流程

```
配置方案 ─发布(完整性检查)─▶ 生成填报单(目标、权重、计分规则冻结副本)
填报中 ─提交─▶ 分公司核对中(并行,全部确认自动推进)─▶ 人力审核中 ─▶ 领导审批中 ─▶ 已通过 ─归档─▶ 已归档(不可变快照)
任一审核节点 ─驳回(原因必填)─▶ 上一节点
```

| 步骤 | 谁 | 做什么 | 系统保证 |
|---|---|---|---|
| 1 配置方案 | 人力审核 | 新建方案版本(可复制上一版)→ 选指标 → 给每个主体分配权重与目标 → 配置考核关系、分管领导、审核节点 → 到人分工 | 权重合计必须 100%,目标值齐全,争议关闭,节点合法,否则不能发布并逐条提示 |
| 2 发布 | 人力审核 | 点「发布方案」 | 方案冻结;每个主体生成一张填报单,指标行带目标、权重、计分规则的冻结副本;历史周期不受后续指标库改动影响 |
| 3 填报 | 部门填报人员 | 在填报单上逐行填实际值(或导入),保存即出分;点「提交填报」 | 有指标未填不能提交;提交后数据冻结,改数只能走调整申请 |
| 4 分公司核对 | 分公司核对人员 | 各分公司并行核对:「确认无误」或「提出争议」(必须写意见) | 全部确认才推进;有争议不能推进;方案里没有需要核对的分公司时自动跳过本节点 |
| 5 人力审核 / 领导审批 | 人力审核、分管领导 | 「审核通过」或「驳回」 | 驳回必须填原因,退回上一节点;每一步谁、何时、从哪到哪、原因全部留痕 |
| 6 计分 | 系统 | 每次保存实际值即算完成率、得分率、得分,并写出计算说明 | 口径唯一,可重复计算;计算过程逐条可复核 |
| 7 汇总 | 系统 | 审批通过时生成部门 / 分公司 / 到人 / 分管领导四个维度的结果与排名 | 加减分、调整落地后自动重算 |
| 8 归档 | 人力审核 | 点「归档」 | 生成带校验和的快照,之后填报单、明细、加减分全部锁定 |

## 4. 功能模块设计

### 4.1 指标库
- **界面**:指标列表(编码、名称、类别、责任板块、计分方式、状态)、指标详情(基本信息 / 计分规则 / 口径说明三页签);阶梯计分的区间表在指标下直接按行维护。
- **规则**:指标编码唯一;停用不删除;版本号 + 「替代版本」表达口径变更;字段改动自动留历史。

### 4.2 考核方案
- **界面**:方案列表(周期、状态、参与主体数、下达指标数、未关闭争议数),方案详情内嵌四张明细表:审核流程节点、参与主体与考核关系、指标下达(网格录入、可导出 Excel)、到人分工(含个人承接项)。
- **规则**:草稿 → 已发布 → 已关闭 → 已归档;发布后配置冻结,要改就复制出新版本;同一周期只有一个生效版本。

### 4.3 指标争议
- 分公司对某项下达可提出争议(理由必填),业务部门/人力给出处理结论(采纳 / 不采纳,结论必填);方案有未关闭争议不能发布。

### 4.4 填报
- **界面**:填报单列表按状态分队列(填报中 / 分公司核对中 / 待人力审核 / 待领导审批 / 已通过 / 已归档)与流程看板;填报单详情 = 指标网格(指标、单位、目标、权重、实际值、完成率、得分率、得分、备注)+ 流程信息 + 加减分明细;明细支持 Excel 导出与批量导入。
- **规则**:实际值保存即算分并显示计算说明;提交后冻结;备注仍可补充。

### 4.5 核对与审核
- **界面**:「待我核对」列表(分公司核对人员)、「待人力审核」「待领导审批」队列;按钮:确认无误、提出争议、审核通过、驳回、归档。
- **规则**:见 §3;审核记录只增不改。

### 4.6 加减分
- 在填报单下按事项登记加分 / 扣分(分值、依据必填),人力审批后计入最终得分;归档后不能再加减分。

### 4.7 数据调整
- 对已提交的**实际值**(源数据)或**得分**(计算结果)发起调整:自动记录调整前值,审批通过即落地——源数据调整触发重算,结果调整直接改得分;每次落地在审核记录里留痕。

### 4.8 汇总与结果
- 四个维度的结果列表(得分、加权得分、排名)+ 结果看板(平均分、最高 / 最低、各单元得分、人员得分)+ 三张报表(组织单元 × 维度矩阵、到人得分、指标完成情况),均可钻取到填报单与指标明细。

### 4.9 归档与审计
- 归档快照带 SHA-256 校验和,不可修改删除;审核记录、调整记录、平台操作日志可按填报单、时间、经办人查询。

## 5. 业务对象总览

| 对象 | 说明 | 关系 |
|---|---|---|
| 组织单元(平台) | 总公司部门、分公司 | 考核主体、责任板块、核对方均引用它 |
| 考核指标 | 指标定义与计分规则 | 阶梯区间从属于指标 |
| 考核方案 | 一次考核的配置集合 | 审核节点、参与主体、指标下达、到人分工从属于方案 |
| 指标下达 | 指标 × 主体 × 权重 × 目标 | 引用指标与主体;争议挂在下达上 |
| 到人分工 / 个人承接项 | 员工 × 板块 × 权重 × 个人系数;员工直接承担的指标 | 从属于方案 |
| 填报单 | 方案 × 主体的一张表 | 填报明细、加减分从属于填报单 |
| 核对任务 | 填报单 × 分公司 | 提交时生成 |
| 数据调整 | 对某条明细的更正申请 | 引用填报单与明细 |
| 审核记录 | 流程动作留痕 | 只增不改 |
| 考核结果 | 四维汇总 | 系统生成 |
| 归档快照 | 周期不可变留存 | 系统生成 |

## 6. 计分规则设计

每个指标声明:方向(越高越好 / 越低越好)、计分方式、完成率封顶与保底、区间或阶梯参数、公式。

| 计分方式 | 得分率 | 适用 |
|---|---|---|
| 完成率线性 | 完成率限定在 [保底, 封顶] | 收入、产量类 |
| 阶梯计分 | 完成率落在哪个区间取该区间得分率 | 满意度、达标类 |
| 区间插值 | 下限 → 0,100% → 100%,上限 → 封顶,线性插值 | 利润类,鼓励超额 |
| 自定义公式 | 用 实际值 / 目标值 / 权重 / 完成率 写公式,直接得出得分 | 事故次数等特殊口径 |

完成率:越高越好 = 实际 ÷ 目标;越低越好 = 目标 ÷ 实际。指标得分 = 权重 × 得分率。主体总分 = 指标得分合计 + 已批准加减分。

示例(市场部,权重合计 100):

| 指标 | 权重 | 目标 | 实际 | 完成率 | 计分方式 | 得分率 | 得分 |
|---|---|---|---|---|---|---|---|
| 营业收入完成率 | 50 | 1200 万元 | 1320 | 110% | 线性,封顶 120% | 110% | 55.0 |
| 利润完成率 | 30 | 180 万元 | 144 | 80% | 区间 60%~120% | 50% | 15.0 |
| 客户满意度 | 20 | 90 分 | 87.3 | 97% | 阶梯:95%~100% → 90% | 90% | 18.0 |
| 合计 | 100 | | | | | | **88.0** |

## 7. 汇总口径

| 维度 | 口径 |
|---|---|
| 部门 / 分公司 | 填报单最终得分,组内排名 |
| 到人 | Σ(所属板块得分 × 分工权重 × 个人系数)+ Σ(承接项得分率 × 承接权重) |
| 分管领导 | 分管主体得分按主体权重加权平均(权重全空则算术平均) |

## 8. 权限与安全

- 六个岗位对应六套权限;流程按钮由系统按当前节点的审核岗位把关;
- 人力、管理员看全部;部门 / 分公司只看本单元;分管领导只看分管主体;到人结果只看本人;
- 平台账号体系提供密码策略、登录失败锁定、停用即失效;审批、驳回、归档、调整落地全部留痕;
- 「分管范围」在开源版平台上通过按方案自动生成的共享规则实现,不依赖企业版组织树深度。
